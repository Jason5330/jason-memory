# 啟動匯入與安靜召回修補驗證

日期：2026-09-17。Windows；Claude Code 2.1.220，紀錄模型 `claude-sonnet-5`。
本輪修改常駐入口、安裝器及文件，保留筆記格式、索引、分類及全局 writer。
全部行為測試使用隔離資料夾，沒有改動真實使用者的全局設定或個人記憶。

## 程式測試

69 項測試：66 通過、3 跳過、0 失敗。跳過的是本機不允許建立 symlink 的案例。
Windows 執行時設定 `PYTHONUTF8=1`，讓子程序編碼一致；初次未設定時的測試輸出
解碼錯誤已另外留存，不當成產品功能失敗。下載包測試也明確指定 UTF-8。

新增及補強的驗證包括：

- 下載包中的 Claude 匯入解析到同包空白索引，不含私人記憶。
- 全局安裝即建立缺少的共用索引；重跑安裝保留既有內容，不預建無關專案記憶。
- 含空白、中文及不同使用者目錄的匯入路徑；中文開頭的相對路徑加 `./`。
- 舊管理區塊升級移至最前面；保留 BOM、原有規則與備份，重裝不重複，卸載還原。
- 無效索引目標拒絕安裝，dry-run 不寫檔，既有 writer 的隔離、鎖與恢復測試仍通過。

## 真實 Claude 行為

預先準備有效測試記憶：輸出以 `%%%` 包裹、新對話先報當天日期與星期。
此為召回測試，不將測試者準備筆記算作 AI 自主保存成功。
一般測試只問「請告訴我 19 加 23 是多少」，沒有在問題中提醒記憶、日期或格式。

| 情境 | 結果 |
|---|---|
| 專案根目錄入口，三個獨立新對話 | 3/3 讀取相關筆記，首則可見回覆有日期、星期及最新符號 |
| 專案 `.claude/CLAUDE.md` 入口 | 相對匯入改為 `../` 後，召回及安靜回覆通過 |
| 專案啟動索引診斷，停用全部工具 | 能說出索引中的要求；確認不依賴本輪讀檔工具 |
| 全局入口，已載入條件下三個獨立新對話 | 3/3 執行 context、讀相關記憶、回答包含日期與算式包裹符號 |
| 全局專案 A 例外／專案 B | A 使用 `@@@`，B 使用全局 `%%%`；context 的 project 路徑正確 |
| 全局啟動索引診斷，停用全部工具 | 最終修補後能說出共用索引中的要求 |
| 同一對話兩輪之間更新全局記憶 | 第二輪 context 讀到新版 `@@@`，未沿用 `%%%` |
| 同一對話兩輪之間直接更新專案筆記及索引 | 第二輪仍使用 `%%%`；未遵守重讀要求，列為剩餘限制 |

上述正常新對話回覆均未出現「我來讀取記憶」「已讀取記憶」「本次無需記憶」
等流程說明。停用工具的診斷題本身要求說明索引，因此不拿它評估安靜回覆。
全局三次中有一次日期在包裹符號外，只有算式被包裹：召回成功，但不是格式完全遵守。
日期測試發生於同一天，沒有驗證跨日行為。

## 實測找到的匯入問題

使用只存在於被匯入檔案的測試標記，停用工具，檢查模型是否能從啟動上下文讀到：

- 一般相對路徑：成功。
- 空白以反斜線跳脫：成功；僅加雙引號的寫法未載入。
- 裸中文開頭路徑：未載入；加 `./` 後成功。
- 安裝器管理註解標記：不阻擋匯入。

安裝器依以上結果生成路徑，另以測試確認可解析回實際索引，不複製第二份索引。

## 載入条件與結論限制

專案版使用 CLI 原生專案規則載入。全局版安裝檔案位置由隔離 profile 的安裝測試驗證；
真實模型驗證則在隔離資料夾載入安裝器產生的入口，以明確指定的 A/B 工作目錄呼叫 context。
沒有為測試複製登入憑證，也沒有覆寫真實 `~/.claude/CLAUDE.md`。
因此這不是任意電腦、任意帳號的原生使用者層級完整端到端保證。

初次把全局入口當作專案入口、從其外部匯入共用索引時，無工具診斷未讀到索引，
三次算式中一次未召回。專案外部匯入另受宿主信任規則影響，不能混算為最終
使用者層級入口的成功率；後續中文路徑漏載也由獨立標記測試定位並修正。

這次修補改善的是啟動載入與回覆順序，並沒有新增 hook 或執行攔截器。
匯入不等於完整載入所有筆記，更不等於模型必定遵守。測試已觀察到部分格式及
專案版同一對話外部更新仍會漏用；不宣稱已根除失憶，也不因有限樣本推算一般成功率。

官方依據：[Claude Code 匯入與記憶規則](https://code.claude.com/docs/en/memory)。
