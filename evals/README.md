# 情境驗收執行方式

`evals.json` 是測試者的案例清單；只將 `prompt` 交給受測 Agent，不提供
`expected_output` 或本文件。使用假的測試資料，不連結真實客戶或通知服務。

每個案例與版本使用不同目錄。複製待測的 `AGENTS.md`、`CLAUDE.md`、
`SKILL.md`、`templates/`、`tools/`，以索引範本初始化 `.jason-memory/MEMORY.md`。
明確讓 Agent 讀取該專案的常駐規則。原版與新版分別使用凍結的檔案快照，
不要在執行中替換規則。這驗證載入後的規則行為，不等於驗證 host 自動載入。

| 案例 | 額外前置條件 |
|---|---|
| 1 | 同一 Agent 逐輪送出六則訊息，等每輪完成並保存快照才送下一輪；不可一次告知完整序列 |
| 7 | 複製 `fixtures/header-preview.html` 到受測專案；記憶仍為空 |
| 13 | 固定測試日期與時區，例如 2026-09-16 Asia/Taipei；停用真實排程及外部通知，驗證未排程時的誠實回覆 |
| 14 | 在使用者可維護的專案條款中加入「本專案報表都必須保留原始資料。」 |
| 15 | 在使用者可維護的專案條款中加入「本專案所有報表的標題必須填滿淺藍色。」；允許更新此條款 |
| 16 | 複製案例 1 第六輪的記憶庫到同範圍的測試專案，以全新 Agent、無前輪對話執行；不得在提示中洩漏預期顏色 |

其他案例從空記憶開始。每案保存使用者可見回覆、筆記及索引、規則變更與
產物，執行兩支健檢。人工覆核需求的範圍、通報及例外；對 Excel 直接讀取
儲存的欄位樣式，不能只以回覆「已套用」算成功。腳本結構健檢不等於語意驗收。

結果須交代版本、執行環境、是否全新對話、每案通過／失敗及證據限制。
每版每案只跑一次不足以估計漏記率，應在實際使用的 host／模型重複驗證。
測試中禁止的 Git／網路動作屬隔離條件，所以「沒有 Git 提醒」也不能單獨
當成未受限制的日常行為保證。
