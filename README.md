**永久移除：** 關閉 AI 工作階段後，雙擊 `UNINSTALL.bat`，清除本份套件的框架、
專案記憶及目前使用者的全局記憶安裝；保留其他設定與工作檔案。
刪除不可復原，範圍、預覽及例外見 [清除說明](docs/uninstall.md)。

一套以 Markdown 檔案為基礎的 AI Agent 記憶協議。用一份索引管理多則小筆記，讓 Agent 在新任務中找回經驗、使用者偏好及未完成工作的接續資訊。

**主動讀取、主動判斷需求、主動記錄、寫入後健檢並通報。** 使用者不必說「記住」，AI 也應自行保存有依據、未來有用的需求與經驗。不需要資料庫或伺服器；新版提供 Claude hooks 與一致性寫入工具，預設也沒有固定的索引行數／位元組門檻。

**效能修補：** 簡單偏好可用一次 `remember` 呼叫完成；不再先讀多份說明、手填事實
欄位或建立暫存計畫。修正全局 hook 誤擋框架 SKILL.md，移除普通工具後的整庫掃描，
保留保存證據與跨筆記更正保護。詳見 [快速流程](docs/memory-runtime.md#日常快速流程)。

**一般使用者：下載 ZIP → 解壓縮 → 用 AI 開啟資料夾。Claude 建議先執行 INSTALL.cmd 接通 hooks；不重建記憶，不需要 Git、clone、commit 或 PR。**

[下載一般使用版 ZIP](https://github.com/Jason5330/jason-memory/releases/latest/download/jason-memory.zip) · [開始使用](START_HERE.md)

使用版包含空白記憶索引、常駐規則與健檢工具，不含 `.git` 歷史或任何人的筆記。
需要支援本機檔案與專案規則的 AI 工具，以及 Python 3.9+（可使用 AI 工具內建的 Python）。

**同一台電腦、不同 AI 共用：** 另有獨立的
[全局共用版 ZIP](https://github.com/Jason5330/jason-memory/releases/latest/download/jason-memory-global.zip)。
解壓後執行一次 `INSTALL.cmd`，讓 Codex 與 Claude Code 共用全局偏好，並隔離各專案需求。
其他可存取本機檔案的 AI 可接入通用規則；詳見 [全局版說明](global/README.md)。
原本的專案版維持原用法，兩個版本不會自動遷移彼此的記憶。

新版補上「沒有寫入卻說已記住」的檢查：Claude hooks 核對本輪工具收據與
實際筆記、索引及通知連結；既有偏好可驗證而不重寫。驗證失敗會要求更正，
重試仍失敗則顯示警告。升級後執行新版 `INSTALL.cmd` 並開新對話；保留舊記憶，
不要用空白索引覆蓋。[驗證結果與限制](tests/hooks-validation.md)

## 運作方式

```text
你的專案/
├── AGENTS.md / CLAUDE.md  # 依 host 選用的常駐記憶規則
└── .jason-memory/         # 你的本機記憶庫
    ├── MEMORY.md          # 索引：一行連結＋一句摘要
    ├── verify-before-done.md
    ├── current-project.md
    └── archive/           # 已封存筆記與封存索引
```

任務開始時，Agent 明確讀取 `MEMORY.md`，根據摘要開啟相關筆記；收到需求、叮嚀、糾正或學到可重用經驗時，主動判斷並更新既有筆記或新增筆記，再同步索引、執行健檢並在同輪通報使用者。每輪結束前補查漏記，沒有值得記的內容就不新增。

Claude Code 的入口現在用 `@.jason-memory/MEMORY.md` 在啟動時直接匯入索引。
在第一則可見回覆（包含進度說明）之前，AI 須先讀適用的開場、格式與任務筆記；
簡單問答也適用。後續訊息由 hook 檢查最新內容；完整快照可重用，無 hook 才自行 context。
正常召回保持安靜，不說「我來讀取記憶」「已讀取記憶」或「本次無需記憶」。
只有實際保存、修改、封存才通報，讀寫失敗才說明問題。
匯入只解決索引載入，不保證模型完全遵守；相關筆記仍須讀取，也仍受宿主權限限制。

| 類型 | 記錄內容 |
|---|---|
| `user` | 使用者的身份、專長，以及已確認的持久個人偏好 |
| `feedback` | 持久工作需求與偏好、叮嚀、踩坑教訓、驗證有效的做法 |
| `project` | 專案目標、決策、限制、卡點及未完成工作的下一步 |
| `reference` | 未來會用到的 URL、票單、儀表板或檔案位置 |

`feedback` 的重點是 **Agent 自己判斷該記什麼**：自行發現並修正的錯誤、已驗證的特殊做法，都不必等使用者說「記住」。但要附證據和適用條件；一次測試通過不等於所有情境都有效，尚未確認的推論不提升成持久規則。

筆記範例：

```markdown
---
name: verify-before-done
description: 回報修改完成前確認變更已生效
type: feedback
created: 2026-09-09
updated: 2026-09-09
---

**Why:** 曾遇到修改指令沒有套用成功，但直接回報完成的情況。
**How to apply:** 修改後檢查預期變更；行為有改動時執行相關測試。
```

在索引對應類型下加入：

```markdown
## feedback
- [完成前驗證](verify-before-done.md) — 回報前確認修改真的生效
```

正文、摘要預設繁體中文；欄位名、類型代號及 Why／How to apply 標籤維持英文。

## 安裝

健檢工具需要 **Python 3.9+**，只使用標準函式庫。Codex 使用 `AGENTS.md`，Claude Code 使用 `CLAUDE.md`；其他 Agent 使用其支援的常駐規則檔。[Codex 官方規則載入說明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

### 直接使用下載版（推薦）

1. 下載上方的一般使用版 ZIP，解壓到獨立的一般資料夾，例如桌面。
2. 在 AI 工具中開啟解壓後包含 `AGENTS.md` 的 `jason-memory` 資料夾，建立新對話。
3. Claude 使用者建議先執行 `INSTALL.cmd` 固定 Python 路徑，再開新對話；既有專案請合併設定，勿覆蓋。直接提出工作需求。空白索引已備好；AI 依常駐規則主動判斷需求、寫入並通報。

也可以在 GitHub 選 **Code → Download ZIP** 下載原始碼；原始碼 ZIP 不含個人記憶，
第一次使用由 AI 從範本建立索引。兩種方式都不需 Git，也不要執行 `git init`。
若看到 `master`／`Create PR`，那是宿主 App 的 Git 介面，不是記憶功能；請改開
新解壓的獨立資料夾，避免置於其他儲存庫內。詳見 [開始使用](START_HERE.md)。

### 加入已存在的其他工作專案

1. 下載本框架。它可以放在專案的 `jason-memory/` 子目錄或另外的固定位置。
2. 在專案內建立記憶目錄，預設 `.jason-memory/`；索引不存在時，把 [索引範本](templates/MEMORY.md) 複製為 `MEMORY.md`。重跑安裝時保留既有索引與所有筆記。
3. 把 [常駐規則範本](templates/standing-rules.md) 的「記憶（Jason-memory）」一節合併到專案根目錄的 `AGENTS.md` 或 `CLAUDE.md`。已有該節時更新該節，保留其他規則；不要重複附加。替換兩個佔位符：
   - `<MEMORY_ROOT>`：實際記憶路徑，例如 `.jason-memory`。
   - `<FRAMEWORK_ROOT>`：框架原始碼路徑，例如 `jason-memory` 或絕對路徑。
4. 一般資料夾直接略過 Git 設定。只有目標已知使用 Git 時，才將記憶目錄加入 `.gitignore`；若已知被追蹤，說明此具體問題，不擅自更動既有資料。不為記憶啟用而探測、初始化 Git，也不建立監控或提交提醒。
5. 確認套用後的規則沒有佔位符殘留，索引及規則指定的 `SKILL.md`、兩支健檢工具都存在，然後執行健檢。

Claude Code 另需在記憶入口最前面加入一行實際匯入，不能放在反引號或程式碼區塊內。
專案根目錄的 `CLAUDE.md` 用 `@.jason-memory/MEMORY.md`；若入口放在
`.claude/CLAUDE.md`，用 `@../.jason-memory/MEMORY.md`。匯入相對於規則檔本身，
不是終端機工作目錄。自訂路徑含空白時以反斜線跳脫空白（如 `@../shared\ memory/MEMORY.md`）；
不要只用引號包住整條路徑；相對路徑以 `./` 或 `../` 開頭，避免中文開頭的路徑漏載。
先建立缺少的索引，既有索引不覆寫。Codex 不使用此匯入語法。
[Claude Code 匯入說明](https://code.claude.com/docs/en/memory#import-additional-files)。

**不需要修改 `.claude/settings.json` 或註冊任何事件。** 只複製框架但沒有建立記憶目錄、套用規則，記憶流程不會自動啟用。

若直接在本框架專案工作，根目錄的 [AGENTS.md](AGENTS.md) 和 [CLAUDE.md](CLAUDE.md) 已指向本機 `.jason-memory/` 與本專案的工具；它們不是供其他路徑直接複製的安裝範本。更新規則後開啟新對話，確認 host 有載入常駐規則。

也可以把這段提示詞交給 Agent：

```text
請在目前專案初始化 Jason-memory：
框架原始碼位於 <框架絕對路徑>。
建立 .jason-memory；只有 MEMORY.md 不存在時才使用 templates/MEMORY.md
初始化，保留既有索引與筆記。
依目前 host 選用 AGENTS.md（Codex）或 CLAUDE.md（Claude Code），將框架的
templates/standing-rules.md 合併進去；已有記憶節則更新，保留其他規則。替換
<MEMORY_ROOT> 和 <FRAMEWORK_ROOT> 為實際路徑。
把回覆前召回規則放在記憶入口最前面。Claude Code 另加入相對於 CLAUDE.md
所在位置的實際 @ 匯入行，讓索引在啟動時載入；不要放在程式碼區塊或反引號內。
一般資料夾不需要任何 Git 操作；只有目標已知使用 Git 時才設定記憶目錄的
忽略規則。不要為記憶啟用探測或初始化 Git、連接遠端，Claude hooks 使用新版安裝工具合併，保留其他設定。
啟用主動判斷：使用者清楚表達的持久需求、叮嚀、偏好、糾正、專案限制，
以及 AI 自行發現的可重用踩坑經驗，都按協議判斷並保存，不等「記住」指令。
每則訊息（含第二輪以後）開始處理前重新判斷；一次性資料與可重用格式要求
分開看。新要求須在交付檔案或最終回覆前保存、同步索引、健檢並同輪通報。
每輪結束前再補查漏記，不因上一輪沒有記憶就略過本輪。
檢查索引及框架路徑，跑兩支健檢工具，簡短回報安裝結果。
不要監控 Git 狀態、盤點未追蹤檔案、提醒或詢問 git add/commit/push。
不要附「尚未提交，需要的話再說」；只有使用者要求或當前任務確實需要時才做 Git 工作。
```

完整協議：[SKILL.md](SKILL.md)。

## 日常使用

1. **讀取**：任務開始先讀索引，再開啟相關筆記。若工具輸出被截斷，要分段續讀，不要把未顯示的部分當成不存在。
2. **判斷並更新**：收到新需求或發現經驗時就判斷，不只在結束對話時做。先去重；同一件事更新原筆記並更新日期。每則筆記聚焦一件事，一項未完成工作使用一則持續更新的 `project` 筆記。
3. **驗證**：筆記與索引更新完，執行兩支健檢工具。工具只讀取、回報，不會自動修改筆記。
4. **整理**：出現重複、過時或摘要不清楚的內容時，合併或封存。準備清空對話、壓縮上下文或換新任務前，同步接續工作所需的資訊。
5. **通報**：實際變更後同輪說明記了什麼、原因、範圍與筆記連結，附索引大小和健檢結果。沒有變更就不列空白分類；使用者明確要求保存但未保存時才解釋原因。

不要重複記錄原始碼、Git 或專案文件已經提供的實作事實；但當次檔案已套用格式，不代表用戶的持續要求已被記錄。只有既有記憶或常駐規範明確寫了相同要求與範圍，才略過重複保存。對可能改變的數值，優先記錄查詢位置，使用前重新確認。

## 何時主動記憶

判斷依據是「使用者是否清楚表達或已有證據，以及未來是否有用」，不是有沒有出現「記住」關鍵字。

**每則訊息都重新判斷，包括同一任務的第二輪與後續補充。** 上一輪是一次性任務，不代表下一輪提出的格式規範也是一次性。開始處理本輪要求前，分開辨識「資料／操作」與「可重用要求」；辨識出的新要求要在送出檔案或最終回覆前完成保存、健檢與通報。

| 情境 | 行為 |
|---|---|
| 「以後的報表都保留原始資料」 | 主動保存為 `feedback`，不用另問是否記住 |
| 隨機產生資料後補充：「輸出的表格，欄位標題都必須填滿淺藍色」 | 記住本專案的表格格式要求；隨機姓名電話仍不記 |
| 「只把這個檔案的標題列改成淺藍色」 | 修改當次檔案，不推成通用偏好 |
| 「這次測試資料必須正好三筆」 | 即使有「必須」，仍是一次性數量要求 |
| 「這次先不要畫圖」 | 當次遵守，不推成持久偏好 |
| 「本專案必須能離線使用」 | 未有其他文件記錄時，保存為 `project` 限制 |
| 使用者更正之前的要求 | 更新原筆記，明確縮小或替換適用範圍 |
| AI 自己查出某個可重犯的錯誤 | 保存觸發條件、失敗證據與已驗證的預防／解法 |
| 尚未驗證的解法或猜測的用戶偏好 | 不當成持久規則；必要的待查問題可留在 `project` |
| 重複、機密值或使用者說不要記 | 略過，不換個筆記繼續保存 |

把來源與適用條件寫進現有筆記內文即可；四種類型、frontmatter、索引與兩支健檢工具的使用方式維持原樣。

不要求使用者加上「以後」才記住規範。描述一類輸出或工作方式的要求，預設限於目前專案；明確只指當次檔案的操作則當次遵守。上述顏色是判斷示例，不是框架預設或所有使用者的偏好。

更正偏好時更新原來源：若舊要求只存在使用者可維護的常駐規範，就更新那一條並通報，避免新筆記與舊規範在下次對話互相衝突。原來源無法修改時，明確說明尚未同步。

「以後處理試算表記得保留公式」是工作叮嚀；「明天下午三點提醒我」則需要外部排程與通知管道。本框架可以用 `project` 記錄待辦與絕對日期／時區，但記錄成功不代表已設定定時提醒。

## 記憶通報與 Git 界線

每次主動記憶後必須通知，例如（僅為格式示例）：

```markdown
已主動記住：本專案的報表需保留原始資料。原因：後續報表都會用到這項要求。
記憶：[報表要求](.jason-memory/report-source-data.md)。健檢通過；索引 12 行／640 bytes。
```

通知中的連結與健檢數字必須使用實際結果。寫入或健檢失敗要明確說明；不能只有口頭說「記住了」。同輪多筆變更可合併通報，無變更不必通報「沒有記憶可存」。

**記憶流程不包含 Git 狀態監控。** 普通資料夾不做 Git 檢查；只有已知使用 Git 的安裝目標才處理 `.gitignore`，不代表日後每次建立檔案都要檢查是否追蹤或提交。一般記憶、安裝及工作完成回覆，都不附「尚未 git add/commit，需要的話再說」。只有使用者要求版本控制工作，或當前開發／審查任務確實需要時，才使用 Git；已授權的提交與推送直接完成。這也不代表自動提交所有檔案。

## 健檢

以下指令在框架根目錄執行；從其他目錄使用時，請填入工具與記憶庫的實際路徑。路徑有空格時加引號。

```bash
python tools/jason_check.py <MEMORY_ROOT>/MEMORY.md
python tools/jason_doctor.py <MEMORY_ROOT>
```

### 大小統計：jason_check

預設只回報索引的行數和實際位元組數；超過 200 行不會因此報錯。以分塊讀取統計，避免把大型檔案一次載入記憶體。

| 結束碼 | 意義 |
|---|---|
| `0` | 統計完成，沒有超過任何已設定門檻 |
| `1` | 超過使用者自行設定的警告門檻 |
| `2` | 超過使用者自行設定的預算 |
| `64` | 指令用法錯誤 |
| `66` | 無法讀取檔案 |

### 一致性檢查：jason_doctor

檢查斷鏈、逃出記憶庫的路徑、從索引無法到達的筆記、重複檔名、必要欄位、日期與非空 Why／How to apply 說明。兩則互相連結卻沒有索引入口的筆記，也會被判定為孤兒。

結束碼 `0` 表示未發現問題，`1` 表示發現問題或未完成檢查。只檢查結構時：

```bash
python tools/jason_doctor.py <MEMORY_ROOT> --no-schema
```

語法規則：

- 索引用平面清單 `- [標題](slug.md) — 摘要`，也接受 `+`、`*`。副檔名可用 `.MD`；完整檔名大小寫仍依作業系統。
- 支援錨點、尖括號和連結標題；檔名使用不含空格的 slug。參照式連結、巢狀清單等 Markdown 擴充不在協議範圍。
- 索引入口必須是完整的一般連結；未閉合的括號／標題、圖片及跳脫文字不算有效入口。
- HTML 註解、程式碼範例中的連結不算有效入口。正文的 `[[slug]]` 可連到其他筆記；未建立的前向連結會提示，但不直接判錯。
- 索引與筆記需為 UTF-8（可含 BOM）。無法解碼的檔案或無法巡覽的目錄會回報未完成檢查，避免誤判正常。
- frontmatter 是受限的 `key: value` 格式，不是完整 YAML；可讀取 `metadata:` 下的必要欄位。
- Why／How to apply 的說明可以寫在標籤後或下一行。格式檢查不能證明內容真實或方法有效。

doctor 保留 **1 MiB 索引／4 MiB 單篇筆記的解析保護**，超過時明確回報未完成檢查。這是診斷程式的資源限制，不是 200 行限制、host 載入上限或寫入攔截。

## 索引整理與可選門檻

索引保持「一行連結＋一句摘要」，內容放進筆記。出現重複或過時內容、讀取成本上升、工具回報截斷時，再整理摘要、合併重複筆記或封存舊主題。不要只為壓低行數而丟棄有用記憶。

若要設定自己的大小預算，以下環境變數仍可使用；**全部預設停用**。值必須是正整數，未設定、無效值、零或負數都停用該維度。

| 變數 | 作用 |
|---|---|
| `JASON_WARN` | jason_check 的行數警告 |
| `JASON_WARN_BYTES` | jason_check 的位元組警告 |
| `JASON_HARD` | 兩支健檢工具的行數預算 |
| `JASON_HARD_BYTES` | 兩支健檢工具的位元組預算 |

獨立健檢只回報；新版 writer 會在健檢不通過時拒絕套用。

**與官方原生記憶的差別：**截至 2026-09-09 核對的 Claude Code 官方文件，原生 auto-memory 索引仍有前 200 行／25KB 的啟動載入限制，接近或超過限制會提示處理。本框架使用獨立專案目錄並要求明確讀取，因此不把原生自動載入限制設成 Jason 的預設硬門檻；實際工具若截斷輸出仍需續讀。[官方說明](https://code.claude.com/docs/en/memory#how-it-works)

## 從舊版升級

本版新增召回、路徑與保存通知 hooks；與早期容量 hook 不同。升級方式及限制見 [runtime 協議](docs/memory-runtime.md)。

- 已安裝本框架者，使用新的常駐規則範本更新記憶節，補上主動需求判斷、同輪通報與不監控 Git 的規則；Codex 專案請確認規則位於 `AGENTS.md`。保留既有筆記、索引與其他專案規則；不需重建記憶庫。
- 曾安裝舊版者，從專案或使用者的 Claude Code 設定中移除指向 `jason_index_guard.py` 的那一筆註冊，保留其他事件處理與設定。本 repo 的變更不會自動改動使用者的外部設定。
- 更新常駐規則，移除舊的「超過 200 行先阻擋」指示。若不需要自訂容量門檻，也清除以前設定的 `JASON_WARN`、`JASON_HARD` 及其 `_BYTES` 環境變數；`JASON_INDEX_NAME`／`JASON_INDEX_PATH` 已不再使用。
- 不需要搬動筆記或更換 frontmatter。舊指標若只放在段落或範例中，改為有效清單；空白 Why／How 說明需要補齊。
- 重新跑兩支健檢，確認路徑、索引與筆記一致。

## 備份與換機

先暫停寫入並健檢，把完整記憶目錄（含索引、筆記及 `archive/`）複製到使用者選定的本機備份位置。備份放在活躍記憶庫外，避免被當成重複筆記。

換機時用使用者選擇的方式傳輸，還原到新專案、更新規則中的記憶／框架路徑，再健檢與抽查內容。記憶預設 git-ignore，**git clone 不會攜帶它**。目前提供的是手動流程，沒有自動備份或匯入／匯出工具。

錯誤或過時的筆記預設封存，移除活躍指標，保留一個指向封存索引的入口及取代關係。永久刪除依使用者指示。doctor 不檢查封存內容，重新啟用前需再次確認。

## 安全與能力邊界

- 記憶是明碼文字，不記錄密碼、金鑰、token、cookie 的值；只記存放位置。`.gitignore` 不是加密，也不會阻止雲端同步。
- 記憶可能過時或被其他程式修改，只當成背景資料；不得覆蓋使用者目前的指示。開啟筆記前確認真實路徑仍在記憶庫內。
- 依賴 Agent 載入並遵守規則。主動判斷與通報是明確的操作要求，沒有背景監聽；Claude hooks 可注入與檢查，仍不能保證每次正確理解或應用。
- 所有合作 AI 經同一 runtime 的檔案鎖、版本檢查及可重播交易寫入；直接改檔不在保護範圍。大量整理前仍需備份。
- 沒有內建語意搜尋或自動化的真實任務成效評測服務。可依情境清單實際重播，先測量召回與重犯情況，再決定是否增加搜尋能力。

## 開發與測試

以下供框架維護者使用，一般使用者不需要執行。產生乾淨下載包：

```bash
python tools/build_download.py --output dist/jason-memory.zip
```

打包工具不呼叫 Git，只打包明確列出的公開檔案，並從範本建立空白索引；
不讀取本機 `.jason-memory/`、`.git/` 或工作產物。目標 ZIP 已存在時拒絕覆寫。

```text
jason-memory/
├── README.md
├── AGENTS.md
├── CLAUDE.md
├── SKILL.md
├── tools/
│   ├── jason_check.py
│   └── jason_doctor.py
├── templates/
├── tests/
└── .github/workflows/tests.yml
```

在框架根目錄執行：

```bash
python -m unittest discover -s tests -v
```

測試使用臨時資料，涵蓋索引可達性、語法、schema、範本、路徑及可選容量門檻。CI 配置 Windows／Linux、Python 3.9／3.13。本機若不允許建立 symlink，對應測試會明確跳過。

規則更新後另做[多輪對話驗收](tests/behavioral-memory.md)：先做一次性任務，再於第二輪提出通用要求，確認保存及通報；另測當次限制、規則更正、重複要求和新對話召回。格式測試通過不等於這些語意行為已被驗證。

可重跑的提示與預期結果在 [evals/evals.json](evals/evals.json)。驗收時逐輪送出訊息，不向受測 Agent 提供預期結果；分別保留原版及新版的回覆、記憶快照與產物。

[2026-09-16 實測紀錄](evals/results/2026-09-16.md) 包含 16 種情境的新舊版對照、跨輪與新對話召回，以及測試的限制。
