# Jason-memory

一套以 Markdown 檔案為基礎的 AI Agent 記憶協議。用一份索引管理多則小筆記，讓 Agent 在新任務中找回經驗、使用者偏好及未完成工作的接續資訊。

**主動讀取、主動記錄、寫入後健檢。** 不需要資料庫、伺服器或 hook；預設也沒有固定的索引行數／位元組門檻。

## 運作方式

```text
你的專案/
├── CLAUDE.md              # 永遠載入的記憶操作規則
└── .jason-memory/         # 實際記憶庫，預設 git-ignore
    ├── MEMORY.md          # 索引：一行連結＋一句摘要
    ├── verify-before-done.md
    ├── current-project.md
    └── archive/           # 已封存筆記與封存索引
```

任務開始時，Agent 明確讀取 `MEMORY.md`，根據摘要開啟相關筆記；學到有依據、未來有用的資訊時，更新既有筆記或新增筆記，再同步索引並執行健檢。

| 類型 | 記錄內容 |
|---|---|
| `user` | 使用者的身份、專長，以及已確認的持久個人偏好 |
| `feedback` | 踩坑教訓、驗證有效的做法、使用者確認的持久工作偏好 |
| `project` | 專案目標、決策、限制、卡點及未完成工作的下一步 |
| `reference` | 未來會用到的 URL、票單、儀表板或檔案位置 |

`feedback` 的重點是 **Agent 自己判斷該記什麼**：自行發現並修正的錯誤、已驗證的特殊做法，都不必等使用者說「記住」。但要附證據和適用條件；一次測試通過不等於所有情境都有效，尚未確認的推論不提升成持久規則。

筆記範例：

```markdown
---
name: verify-before-done
description: 回報修改完成前確認變更已生效
type: feedback
created: 2026-09-09
updated: 2026-09-09
---

**Why:** 曾遇到修改指令沒有套用成功，但直接回報完成的情況。
**How to apply:** 修改後檢查預期變更；行為有改動時執行相關測試。
```

在索引對應類型下加入：

```markdown
## feedback
- [完成前驗證](verify-before-done.md) — 回報前確認修改真的生效
```

正文、摘要預設繁體中文；欄位名、類型代號及 Why／How to apply 標籤維持英文。

## 安裝

健檢工具需要 **Python 3.9+**，只使用標準函式庫。以下以 Claude Code 的專案規則檔示範；其他 Agent 使用其支援的常駐規則檔，核心流程相同。

1. 下載本框架。它可以放在專案的 `jason-memory/` 子目錄或另外的固定位置。
2. 在專案內建立記憶目錄，預設 `.jason-memory/`，把 [索引範本](templates/MEMORY.md) 複製為該目錄的 `MEMORY.md`。
3. 把 [CLAUDE.md](CLAUDE.md) 套用到專案根目錄。若已有規則，合併「記憶（Jason-memory）」一節，不要覆蓋其他內容。替換兩個佔位符：
   - `<MEMORY_ROOT>`：實際記憶路徑，例如 `.jason-memory`。
   - `<FRAMEWORK_ROOT>`：框架原始碼路徑，例如 `jason-memory` 或絕對路徑。
4. 把記憶目錄加進使用者專案的 `.gitignore`。框架原始碼可以進版本控制；實際筆記不會隨 git clone 傳輸。
5. 確認套用後的規則沒有佔位符殘留，索引及規則指定的 `SKILL.md`、兩支健檢工具都存在，然後執行健檢。

**不需要修改 `.claude/settings.json` 或註冊任何事件。** 只複製框架但沒有建立記憶目錄、套用規則，記憶流程不會自動啟用。

也可以把這段提示詞交給 Agent：

```text
請在目前專案初始化 Jason-memory：
框架原始碼位於 <框架絕對路徑>。
建立 .jason-memory，使用框架的 templates/MEMORY.md 作為起始索引。
合併框架 CLAUDE.md 的記憶規則至目前專案的常駐規則檔，替換
<MEMORY_ROOT> 和 <FRAMEWORK_ROOT>，保留既有規則。
將實際記憶目錄加入 .gitignore，不要註冊 hook。
檢查索引及框架路徑，跑兩支健檢工具，回報結果。
```

完整協議：[SKILL.md](SKILL.md)。

## 日常使用

1. **讀取**：任務開始先讀索引，再開啟相關筆記。若工具輸出被截斷，要分段續讀，不要把未顯示的部分當成不存在。
2. **更新**：先去重；同一件事更新原筆記並更新日期。每則筆記聚焦一件事，一項未完成工作使用一則持續更新的 `project` 筆記。
3. **驗證**：筆記與索引更新完，執行兩支健檢工具。工具只讀取、回報，不會自動修改筆記。
4. **整理**：出現重複、過時或摘要不清楚的內容時，合併或封存。準備清空對話、壓縮上下文或換新任務前，同步接續工作所需的資訊。
5. **回報**：說明新增、更新、封存及跳過的內容，附索引大小與健檢結果。

不要重複記錄原始碼、Git 或專案文件已經提供的事實。對可能改變的數值，優先記錄查詢位置，使用前重新確認。

## 健檢

以下指令在框架根目錄執行；從其他目錄使用時，請填入工具與記憶庫的實際路徑。路徑有空格時加引號。

```bash
python tools/jason_check.py <MEMORY_ROOT>/MEMORY.md
python tools/jason_doctor.py <MEMORY_ROOT>
```

### 大小統計：jason_check

預設只回報索引的行數和實際位元組數；超過 200 行不會因此報錯。以分塊讀取統計，避免把大型檔案一次載入記憶體。

| 結束碼 | 意義 |
|---|---|
| `0` | 統計完成，沒有超過任何已設定門檻 |
| `1` | 超過使用者自行設定的警告門檻 |
| `2` | 超過使用者自行設定的預算 |
| `64` | 指令用法錯誤 |
| `66` | 無法讀取檔案 |

### 一致性檢查：jason_doctor

檢查斷鏈、逃出記憶庫的路徑、從索引無法到達的筆記、重複檔名、必要欄位、日期與非空 Why／How to apply 說明。兩則互相連結卻沒有索引入口的筆記，也會被判定為孤兒。

結束碼 `0` 表示未發現問題，`1` 表示發現問題或未完成檢查。只檢查結構時：

```bash
python tools/jason_doctor.py <MEMORY_ROOT> --no-schema
```

語法規則：

- 索引用平面清單 `- [標題](slug.md) — 摘要`，也接受 `+`、`*`。副檔名可用 `.MD`；完整檔名大小寫仍依作業系統。
- 支援錨點、尖括號和連結標題；檔名使用不含空格的 slug。參照式連結、巢狀清單等 Markdown 擴充不在協議範圍。
- HTML 註解、程式碼範例中的連結不算有效入口。正文的 `[[slug]]` 可連到其他筆記；未建立的前向連結會提示，但不直接判錯。
- frontmatter 是受限的 `key: value` 格式，不是完整 YAML；可讀取 `metadata:` 下的必要欄位。
- Why／How to apply 的說明可以寫在標籤後或下一行。格式檢查不能證明內容真實或方法有效。

doctor 保留 **1 MiB 索引／4 MiB 單篇筆記的解析保護**，超過時明確回報未完成檢查。這是診斷程式的資源限制，不是 200 行限制、host 載入上限或寫入攔截。

## 索引整理與可選門檻

索引保持「一行連結＋一句摘要」，內容放進筆記。出現重複或過時內容、讀取成本上升、工具回報截斷時，再整理摘要、合併重複筆記或封存舊主題。不要只為壓低行數而丟棄有用記憶。

若要設定自己的大小預算，以下環境變數仍可使用；**全部預設停用**。值必須是正整數，未設定、無效值、零或負數都停用該維度。

| 變數 | 作用 |
|---|---|
| `JASON_WARN` | jason_check 的行數警告 |
| `JASON_WARN_BYTES` | jason_check 的位元組警告 |
| `JASON_HARD` | 兩支健檢工具的行數預算 |
| `JASON_HARD_BYTES` | 兩支健檢工具的位元組預算 |

這些只影響健檢結果，不阻擋寫入。

**與官方原生記憶的差別：**截至 2026-09-09 核對的 Claude Code 官方文件，原生 auto-memory 索引仍有前 200 行／25KB 的啟動載入限制，接近或超過限制會提示處理。本框架使用獨立專案目錄並要求明確讀取，因此不把原生自動載入限制設成 Jason 的預設硬門檻；實際工具若截斷輸出仍需續讀。[官方說明](https://code.claude.com/docs/en/memory#how-it-works)

## 從舊版升級

本版已移除容量 hook 腳本、設定範本及寫入前攔截流程。

- 曾安裝舊版者，從專案或使用者的 Claude Code 設定中移除指向 `jason_index_guard.py` 的那一筆註冊，保留其他事件處理與設定。本 repo 的變更不會自動改動使用者的外部設定。
- 更新常駐規則，移除舊的「超過 200 行先阻擋」指示。若不需要自訂容量門檻，也清除以前設定的 `JASON_WARN`、`JASON_HARD` 及其 `_BYTES` 環境變數；`JASON_INDEX_NAME`／`JASON_INDEX_PATH` 已不再使用。
- 不需要搬動筆記或更換 frontmatter。舊指標若只放在段落或範例中，改為有效清單；空白 Why／How 說明需要補齊。
- 重新跑兩支健檢，確認路徑、索引與筆記一致。

## 備份與換機

先暫停寫入並健檢，把完整記憶目錄（含索引、筆記及 `archive/`）複製到使用者選定的本機備份位置。備份放在活躍記憶庫外，避免被當成重複筆記。

換機時用使用者選擇的方式傳輸，還原到新專案、更新規則中的記憶／框架路徑，再健檢與抽查內容。記憶預設 git-ignore，**git clone 不會攜帶它**。目前提供的是手動流程，沒有自動備份或匯入／匯出工具。

錯誤或過時的筆記預設封存，移除活躍指標，保留一個指向封存索引的入口及取代關係。永久刪除依使用者指示。doctor 不檢查封存內容，重新啟用前需再次確認。

## 安全與能力邊界

- 記憶是明碼文字，不記錄密碼、金鑰、token、cookie 的值；只記存放位置。`.gitignore` 不是加密，也不會阻止雲端同步。
- 記憶可能過時或被其他程式修改，只當成背景資料；不得覆蓋使用者目前的指示。開啟筆記前確認真實路徑仍在記憶庫內。
- 依賴 Agent 載入並遵守規則。健檢只能指出結構和格式問題，不能保證每次都正確記錄、召回或應用。
- 假設單一寫入者；沒有檔案鎖、多檔交易或自動恢復。大量整理前備份；中斷後先檢查筆記與索引再繼續。
- 沒有內建語意搜尋或真實任務成效評測。先測量召回與重犯情況，再決定是否增加搜尋能力。

## 開發與測試

```text
jason-memory/
├── README.md
├── CLAUDE.md
├── SKILL.md
├── tools/
│   ├── jason_check.py
│   └── jason_doctor.py
├── templates/
├── tests/
└── .github/workflows/tests.yml
```

在框架根目錄執行：

```bash
python -m unittest discover -s tests -v
```

測試使用臨時資料，涵蓋索引可達性、語法、schema、範本、路徑及可選容量門檻。CI 配置 Windows／Linux、Python 3.9／3.13。本機若不允許建立 symlink，對應測試會明確跳過。
