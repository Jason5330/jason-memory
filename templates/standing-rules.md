## 記憶（Jason-memory）

記憶庫：`<MEMORY_ROOT>/`；框架：`<FRAMEWORK_ROOT>/`。
相對路徑以安裝此規則的專案根目錄為準。
任務開始先讀 `<FRAMEWORK_ROOT>/SKILL.md` 與 `<MEMORY_ROOT>/MEMORY.md`，
按索引開啟相關筆記；不要假設 host 自動載入這個獨立記憶庫。

收到使用者清楚表達的持久需求、偏好、叮嚀、糾正、目標、限制，或自己發現
可重用錯誤、驗證特殊解法時，主動判斷未來是否有用。符合條件就依協議先去重，
在同輪新增或更新筆記與索引，不等「記住」指令，也不另問是否要保存。
每輪結束前補查漏記；一次性要求不提升為長期偏好，推測與使用者說不要記的內容不保存。
來源、證據、適用範圍寫入既有筆記內文；維持四種記憶類型與原有格式。

每次變更後執行：

```text
python "<FRAMEWORK_ROOT>/tools/jason_check.py" "<MEMORY_ROOT>/MEMORY.md"
python "<FRAMEWORK_ROOT>/tools/jason_doctor.py" "<MEMORY_ROOT>"
```

確認實際寫入與索引後，同輪主動通報記了什麼、原因、範圍、筆記連結、索引大小
與健檢結果；失敗就說明失敗。無記憶變更不必回報空白分類。
記錄有時間要求的事項不等於建立排程，不可因此宣稱會在指定時間提醒。

記憶流程不監控 Git 狀態、不盤點未追蹤檔案、不提醒或詢問 add／commit／push，
不附「尚未提交，需要的話再說」。安裝時確認記憶目錄的忽略設定即可，只有
設定／路徑改變或出現誤追蹤跡象才重查。使用者要求 Git 工作，或當前任務確實
需要 Git 操作時才執行；已授權的提交與推送直接完成，不再追加詢問。
