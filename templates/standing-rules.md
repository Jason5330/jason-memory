## 記憶（Jason-memory）

### 日常快速流程（優先於下方詳細流程）

Claude hook 已提供完整最新筆記時直接重用；hook 未通知變更且正文仍在上下文時
不再 context、讀 SKILL.md 或健檢。缺少／截斷時才補讀；其他宿主每輪 context。
一項新的簡單偏好，用框架 tools/memory_runtime.py --config 目標設定檔 remember
--scope project --subject user --key STABLE_KEY --value "完整要求" --why "使用者依據"。
沿用目前筆記的事實鍵；工具自動生成欄位、健檢、索引及收據，不再另外 verify。
更正現有值、混合事實與舊筆記才讀完整協議，用 apply --plan - 批次處理；
保留其他事實，不用暫存計畫檔。成功後一句通知含實際筆記連結、範圍與結果。

### 回覆前先召回（此節放在記憶入口最前面）

每則使用者訊息，在第一則可見文字（含進度說明）前，先取得目前完整索引
`<MEMORY_ROOT>/MEMORY.md`，再讀與回覆行為、開場、語言、格式及任務相關的
有效筆記。簡單問答也適用，不先宣告讀取流程；摘要不能取代相關正文。
新對話若完整索引已匯入上下文可使用它；後續訊息重新讀取磁碟索引，避免舊版本。
依筆記適用範圍回覆，目前使用者要求與較高優先規則仍優先；無變更不通報讀取流程。
正常召回不說「已讀取記憶」「已套用偏好」「本次無需記憶」；只在實際新增、
修改或封存後通報，讀寫失敗才說明問題。首次任務讀取完整協議。

記憶庫：`<MEMORY_ROOT>/`；框架：`<FRAMEWORK_ROOT>/`。
相對路徑以安裝此規則的專案根目錄為準。
記憶功能不依賴 Git 或 GitHub，一般資料夾可直接使用。不要為啟用記憶而
執行 Git 指令、建立儲存庫、連接遠端或要求提交。
**每則使用者訊息（含第二輪以後）開始處理前，重新辨識本輪的記憶候選。**
分開判斷一次性資料／操作與可重用的要求；上一輪略過記憶不適用於後續新要求。
「輸出的表格，欄位標題都必須填滿淺藍色」是本專案表格輸出的 `feedback`
要求，即使當次資料是隨機測試資料也應保存，不需要另說「以後」或「記住」。
「只把這個檔案改成淺藍色」則限當次；不能只靠「必須」判斷，示例也不是預設偏好。
產物已套用格式不等於用戶要求已被記住；只有既有記憶或常駐規範已記錄相同
要求與範圍才略過重複保存。辨識出的新要求須在送出檔案或最終回覆前完成
筆記／索引更新、健檢及通報；產檔技能完成不取代這一步。失敗時明說未保存。
更正偏好時更新原來源；若舊要求在使用者可維護的常駐規範，修改那一條並通報，
不要另建與它衝突的筆記。原來源無法修改時明說衝突未同步，不宣稱已解決跨輪召回。

任務開始先讀 `<FRAMEWORK_ROOT>/SKILL.md` 與 `<MEMORY_ROOT>/MEMORY.md`，
按索引開啟相關筆記；不要假設 host 自動載入這個獨立記憶庫。

收到使用者清楚表達的持久需求、偏好、叮嚀、糾正、目標、限制，或自己發現
可重用錯誤、驗證特殊解法時，主動判斷未來是否有用。符合條件就依協議先去重，
在同輪新增或更新筆記與索引，不等「記住」指令，也不另問是否要保存。
每輪結束前補查漏記；一次性要求不提升為長期偏好，推測與使用者說不要記的內容不保存。
來源、證據、適用範圍寫入既有筆記內文；維持四種記憶類型與原有格式。

每次變更後執行：

```text
python "<FRAMEWORK_ROOT>/tools/jason_check.py" "<MEMORY_ROOT>/MEMORY.md"
python "<FRAMEWORK_ROOT>/tools/jason_doctor.py" "<MEMORY_ROOT>"
```

確認實際寫入與索引後，同輪主動通報記了什麼、原因、範圍、筆記連結、索引大小
與健檢結果；失敗就說明失敗。無記憶變更不必回報空白分類。
記錄有時間要求的事項不等於建立排程，不可因此宣稱會在指定時間提醒。

記憶流程不監控 Git 狀態、不盤點未追蹤檔案、不提醒或詢問 add／commit／push，
不附「尚未提交，需要的話再說」。只有目標已知使用 Git 時才在安裝時確認
記憶目錄的忽略設定；普通資料夾略過，不為此探測 Git。只有
設定／路徑改變或出現誤追蹤跡象才重查。使用者要求 Git 工作，或當前任務確實
需要 Git 操作時才執行；已授權的提交與推送直接完成，不再追加詢問。


## 新版 runtime 與 hooks

安裝時一併設定目標根目錄 `.jason-memory.json` 的 memory_root，讀寫都使用
框架 tools/memory_runtime.py --config 目標設定檔；不要沿用第二套 `.ai-memory` 路徑。
依 [runtime 協議](../docs/memory-runtime.md) 用批次 apply 更正所有相關筆記，
每次成功變更在最終回覆末尾通知並連結實際筆記；正常讀取保持安靜。
成功宣告須有本輪 runtime apply／verify 的工具收據及讀回正文，保留完整 JSON 輸出。
要求已存在而需要確認時，用 verify --scope project --note 相對筆記路徑，不重寫。
沒有成功證據就明說未保存／未能確認保存，不編造檔名或健檢結果。
Claude 使用 tools/install_hooks.py --project 目標根目錄 合併事件，不覆蓋其他設定。
