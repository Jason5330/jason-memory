## 自動化驗證

執行 `python -m unittest discover -s tests -v`，Windows 設 `PYTHONUTF8=1`。

新增覆蓋：

- 同事不同帳號、中文／空白路徑、Windows 8.3 暫存路徑；拒絕跳出根目錄及重新導向。
- 同一事實跨兩筆記的部分更正遭拒，批次更正成功；保留同檔其他事實及舊正文。
- 合成 ANNA 職業矛盾、否定句不誤當肯定句、不同人物不混用、職業別名辨識。
- 格式偏好的值保留大小寫及空白，未知自由文字列為待語意核對，不宣稱全無矛盾。
- 兩程序用同 revision 寫入，一方成功、另一方被拒；重新合併後兩筆都保留。
- 交易在各 atomic_write 邊界中斷後重播；索引同步、不使用半完成記憶。
- 新對話、compact、同對話另一寫入者更新、全局／專案隔離、工作目錄改變。
- hook 阻擋已知錯誤路徑及直接 Write/Edit；一般工作檔案可照常操作。
- 保存後漏通知或連錯筆記時補救一次；封存通知須連到實際歷史檔；無變更不通知。
- 安裝保留其他 hooks 與權限、重複安裝不重複註冊、卸載保留記憶、損壞 JSON 先拒絕。
- 兩種乾淨 ZIP 解壓後工具可執行，公開包不含 `.git`、私人筆記或測試日誌。

## Claude Code 實際對話

原生 Claude Code 2.1.220，事件中模型標示 `claude-sonnet-5`。啟用實際 hooks，
隔離載入 project/local 設定，停用原生 auto-memory，避免另一記憶機制干擾。

| 情境 | 實際結果 |
|---|---|
| 專案版新對話，只問算式、無模型讀檔工具 | 第一行使用只存在筆記正文的測試開場字串 |
| 專案版同對話，外部 writer 改開場後再問算式 | 下一輪使用更新字串，未沿用舊值 |
| 全局版相同兩輪測試 | 新對話與後續更新皆正確 |
| 先問一次性算式，第二輪要求所有表格標題淺藍色 | 第一輪沒亂記；第二輪主动保存且末尾附筆記連結與通知 |
| 第三輪更正標題為淺綠色 | 原筆記更新、索引同步、保留歷史，並通報 |
| 第四輪询問目前顏色 | 回答淺綠色，未輸出讀記憶的流程語言 |
| 合成 ANNA：稱呼筆記寫醫生，另一份寫可靠性工程師 | 更新正確筆記的事實欄位、封存過時筆記；稱呼保留，通知含有效筆記及封存連結 |

開場字串沒有寫在索引摘要裡；無讀檔工具仍能回答，加上實際 hook 狀態檔，
可確認啟動注入有執行。全局測試把安裝器產生的設定接入隔離工作區，
不代表已替真實使用者全局安裝。有限樣本不能推論所有模型／版本成功率 100%。

## Codex 共用驗證與限制

以獨立 Codex CLI 開啟 Claude 寫過的同一測試專案，能正確讀回「淺綠色」。
要求改淺黃色時，CLI 回報唯讀／執行政策阻擋，未保存且沒有假稱成功。
因此本次確認跨 AI 讀取相容，**不將這次 Codex 行為測試算作雙向寫入通過**。
同庫不同程序寫入的鎖、版本衝突與合併恢復另由自動化測試驗證。

## 修補過程發現的邊界

乾淨 ZIP 測試找出 Windows 短路徑誤判，已修正並重測。保存通知檢查也從
「檔名出現在回覆」改成查核實際 Markdown 目標，避免連錯檔案；封存回傳可用歷史路徑。
所有 hook 都不是任意 shell 寫入的安全沙盒，也不是完整自然語言矛盾判斷器。
大索引／正文超過注入預算會明示需補讀；Stop 最多補救一次，不形成無限循環。

完整使用方式與限制見 [runtime 協議](../docs/memory-runtime.md)。

## 2026-09-18 保存證據修補（proof-20260918）

另行重現使用者回報的「已說保存，但沒有筆記」：空白庫啟動後，向 Stop 提供
含不存在筆記連結及「健檢通過」的成功文案。舊版回傳空結果，因為只檢查有
檔案變更的情況；修補版回傳 block，要求實際保存、驗證既有筆記或撤回成功宣告。
重試仍無證據則回傳 continue=false、systemMessage 與 stopReason，不靜默放行。

新增 19 項測試，總共 115 項；本機 Windows 111 項通過、4 項 symlink 測試略過。
覆蓋繁簡中文／英文宣告、沒有啟動基線、空白庫結構健檢通過但未保存、失敗工具、
過期或不同根目錄收據、回覆自行編造 JSON、連錯筆記、檔案驗證後遭修改／刪除、
索引損壞、索引修復、同輪多次保存、全局保存，以及已存在偏好的免重寫驗證。
引用、範例、失敗說明及一般產檔回報不應引發保存通知。

原生 Claude Code 2.1.220（事件標示 claude-sonnet-5）的額外隔離實測：

| 情境 | 觀測結果 |
|---|---|
| 專案版要求回報先結論、後細節 | 實際建立筆記；PostToolUse 收到 apply/verify 收據；通報連結有效 |
| 同對話再確認已保存、要求不重寫 | 執行 verify；筆記修改時間及版本不變，本輪取得新收據 |
| 全局版第一次測試 | 模型把測試邊界理解得過窄，只口頭說記住；hook 介入後更正為未保存，磁碟確實無筆記 |
| 全局版該測試下一輪 | 實際新增全局筆記並回傳本輪收據，通報有效 |
| 明確允許測試目錄內保存偏好後，重做全局兩輪 | 第一輪實際保存；第二輪 verify，筆記修改時間及版本不變；兩輪皆有工具收據 |

全局測試仍使用安裝器生成的隔離設定，沒有修改真實使用者全局設定。
這次未直接測試 MiniMax 服務；重播的是回報中的失敗情境，不能聲稱已測得
MiniMax 的成功率，也不能因 Claude 測試通過就推論其他模型不會出錯。
Stop 無法收回已顯示的文字；核對收據不等於理解全部自然語言，也不能證明
筆記內容一定符合原始意圖。這些限制不以「健檢通過」掩蓋。
