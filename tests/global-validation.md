## 實測發現並修正

1. 重複保存在其他筆記加入後會重排索引：保留既有位置並驗證 no-op。
2. JSON 轉義使合法大筆記的 journal 超限：上限涵蓋最壞跳脫倍率。
3. 封存後冷啟動找不到舊資料：交易同步維護封存索引與主索引入口。
4. Windows 8.3 暫存路徑與 CRLF 造成驗證誤判／統計差異：解析實體路徑，暫存驗證使用一致的 UTF-8/LF 寫入。
5. Claude 初測更正時新增替代筆記再封存舊筆記，且偶爾通報缺少連結：
   明訂 slug 是穩定識別碼、更正使用原地更新；安裝入口也強調可點選連結與健檢。
   上表的原地更新及最後三輪測試是修改後重測結果。

## 驗證界線

為保留真實使用者設定，安裝器的原生全局檔案寫入是在隔離 profile 測試；
真實 AI 行為測試將**安裝器產出的同一段入口**交給 Codex 隔離代理，
或透過 Claude 的 session system-prompt 入口載入，再使用共同的安裝目錄。
因此這份紀錄證明跨模型的實際檔案讀寫、語意判斷與召回，
不等於在使用者真實全局設定上驗證了每個 GUI／宿主的自動載入。

另曾用 Codex CLI 0.137.0 的 workspace-write 沙盒啟動測試；該環境拒絕了
writer 命令，模型如實回覆「尚未保存」。未把這次當成共用成功，未放寬或繞過
其安全限制；後續改用有既定檔案工具權限的 Codex 隔離代理執行。
安裝記憶入口本身不授予沙盒額外權限，使用者仍須讓所選工具能讀寫共用 home。

其他 AI 的 generic 入口已驗證匯出，但未逐一執行其他廠商模型；純網頁聊天、
跨電腦同步、移動專案後自動遷移不在此版本範圍。
「是否值得保存」仍由載入規則的 AI 判斷；健檢能檢查結構與索引，不能保證
所有模型每次都做出正確語意判斷。有限情景的通過不代表百分之百不漏記。
